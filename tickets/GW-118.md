## Description

Booking now returns `eta_confidence` (BOOK-412) but the gateway's Pydantic response model
`ShipmentOut` declares only `id, reference, origin, destination, carrier_code, status,
eta`. Because the gateway re-serialises through the model, the field is silently dropped
before it reaches the web app.

Proposed change:

```python
# TODO GW-118: add eta_confidence to ShipmentOut
class ShipmentOut(BaseModel):
    ...
    eta_confidence: float | None = Field(default=None, ge=0.0, le=1.0)
```

It must be optional so the gateway keeps working while booking's flag is off or when
talking to an older booking version.

## Acceptance criteria

1. `ShipmentOut` has `eta_confidence: float | None` constrained to 0..1, default `None`.
2. `GET /api/shipments/{id}`, `POST /api/shipments` and `POST /api/shipments/{id}/reserve`
   pass the value through when booking sends it.
3. A response without the field still validates.
4. A pytest using `respx` or `httpx.MockTransport` covers present and absent cases.
5. `pytest -q` is green.
