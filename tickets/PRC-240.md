## Description

The analyzer report from the Q4 cleanup flags `Kestrel.Pricing.Tariffs.LegacyTariffLoader`
as having zero references. The name suggests it was superseded by `CsvTariffLoader`. Can
we delete it?

## Resolution

**No. Do not delete or rename it.**

`LegacyTariffLoader` implements `ITariffLoader` and has no static reference in code, but it
is selected **by name from configuration**. `appsettings.json` contains:

```json
"TariffLoader": "Kestrel.Pricing.Tariffs.LegacyTariffLoader"
```

and `TariffLoaderFactory` resolves that string with `Type.GetType`. Production runs on this
loader (it reads the pipe-delimited export from the old carrier-contract system);
`CsvTariffLoader` is the second implementation, the factory default, used for onboarding
and local development. Removing the class
would make pricing fail at start-up on every pod.

## Acceptance criteria (for the investigation)

1. Identify how the class is loaded. Done: reflection through `TariffLoaderFactory`.
2. Confirm which environments use it. Done: production and staging.
3. Record the finding where the next person will look. Done: this ticket, ADR-0003
   (amended), `runbooks/pricing-tariff-reload.md`, change-management section 4.
